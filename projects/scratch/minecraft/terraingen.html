How to make Minecraft Terrain

Before reading this article, I would advise that you take a look at the following resources, they will really help your understanding of the concepts illustrated here:

  • Reinventing Minecraft World Generation by Henrik Kniberg - YouTube
  • The World Generation of Minecraft - Alan Zucconi, and it's video How Minecraft Actually Works - YouTube
  • Density Function - Minecraft Wiki
  • World Generation - Minecraft Wiki
  • Deepslate - Misode - Github

If you haven't ever looked into Minecraft's source files before, some concepts illustrated below may seem a little unfamiliar.

Introduction

In my own projects, I have worked with Minecraft-style terrain. Simple maths joined together seems to be able to create unique, unpredictable, yet controlled worlds. Many Minecraft clones attempt to recreate this effect, but fall short due to one small detail: 3D noise.

Of course, in a 2d world, this may not make sense. Why should I use 3D noise when I am moving in only two dimensions? For a 3D world, you should use 3d noise, for a 2d world, such as the one we will build today, you should use 2D noise.

But what is noise? In short, noise is controlled chaos. Noise is a mathematical function where you allocate positions in a "grid" to have values, and then interpolate them, blend them together, so there are no truly jagged edges, and you get smooth lines.

Here is an image of "White Noise" - each pixel has no concept of it's neighbours, it is randomly "on" or "off", just like an old TV: ![[Pasted image 20250527203203.png]] Now in Minecraft, this would not look like very pleasing terrain, no matter the direction in which you sample it.

If this 256x256 grid of pixels was your world, it would be very difficult to traverse. So how about we go ahead and smooth the pixels out, ensuring that there are no sudden jumps: ![[Pasted image 20250527203420.png]] Suddenly, our terrain would look much nicer - there are no sudden changes in height, the transition from white to black is much harder to track, now rather than just a fixed on and off, its a gradient.

However, we still have an issue. We have no real way to predict the next pixel. Yes, we have interpolated the heights, but it is too unpredictable, we have no input on this system.

This is where our "Proper" noise comes in. There are two common types of it: Simplex, and Perlin.

Simplex noise looks a bit like this: ![[simplex.png]] Perlin noise looks like this: ![[perlin.png]]

To make the terrain look a little more "exciting", we can add octaves, also known as roughness: ![[Pasted image 20250527204339.png]] However, how should we actually sample the terrain from this? You could simply say the lighter the colour the higher the terrain is, but this comes with a few caveats. In this image, we can see that there is a mysterious lack of overhangs in the terrain, something that is very unique to Minecraft:

This is where most clones fall short - Minecraft does not derive it's heightmap directly from the noise, it uses a more complex system.

Density Functions

Minecraft uses 3d noise, but for this article, we will call it 2d noise.

If we take our noise image from before, and say that any block with a brightness less than 128 (half) is solid, and anything higher is air, this is our result: ![[Pasted image 20250527205039.png]] This does have a vague Minecrafty feel to it, but it still isn't traversable.

This is why Minecraft uses this noise, but with a height bias - the closer you are to bedrock, the more "solid" the ground is. This means that at around sea level, the ground is pretty solid. You can picture the height bias as a "gradient" such as this: ![[Pasted image 20250527205252.png]] When we blend them together, we get some remarkably plausible terrain, complete with some overhangs and the odd floating island

![[Pasted image 20250527205425.png]]

Using Misode's Density Function viewer, we can see this ourselves using a single noise: ![[Pasted image 20250527210208.png]]

However, Minecraft does not use a single noise for it's terrain: it actually uses 60! There are 3 that influence terrain shape directly: Continentalness, Erosion, and Weirdness

Continentalness is the broad scale of terrain, whether the land should be mainly, well, land, or it should be ocean.

Erosion is responsible for those overhangs, and weirdness is responsible, in terrain generation for "peaks and valleys", also known as ridges.

Minecraft does lots of math to these, and answers the overall question: should the block at x,y,z be solid, or not.

However, we have missed a small detail.

Splines

Normal noise does not cause those sudden plateaus that we get in Minecraft. What gives? Minecraft uses maths called "Splines", which allow the noise to remain continuous, but suddenly jump to a higher/lower value when it reaches a threshold. This is what allows for those sudden jumps from ocean to land, such as here: ![[Pasted image 20250527211018.png]]

Using a hard value, such as 

if (noise > 0.4){
	noise = 0.8
}

would not look nice, having random towering cliffs would remove the immersion somewhat.
